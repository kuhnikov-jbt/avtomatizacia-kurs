# Установка набора правил в проект клиента

Этот файл читает Claude на аккаунте клиента. Клиенту здесь читать нечего: Claude всё сделает сам
и задаст вопросы по одному.

## Что ты сейчас делаешь

Ты ставишь в рабочую папку клиента набор файлов, по которым Claude потом работает каждый день:

| Файл | Что в нём | Когда ставить |
| --- | --- | --- |
| `CLAUDE.md` | правила работы Claude | всегда |
| `aboutme.md` | кто клиент, чем занимается бизнес, цифры, системы | всегда |
| `sostoyanie.md` | файл состояния длинной задачи, переживает сжатие разговора | всегда |
| `resheniya.md` | журнал решений владельца с датами | всегда |
| `platnye-servisy.md` | платные сервисы, цена за единицу, дневной лимит | если клиент пользуется платными сервисами |
| `zhurnal-pravok.md` | журнал правок сайтов и рабочих систем | если Claude будет править сайт, CRM, учётную систему |
| `.claude/settings.json` | запрет и хук: Claude не может ни открыть, ни прочитать командой файл с ключами | если в папке есть или будет файл с ключами |

Все файлы лежат рядом с этим, по тому же адресу. Адрес, по которому ты открыл этот файл, без имени
`USTANOVKA.md` на конце, дальше называется **база**.

Что должно получиться в рабочей папке клиента:

```
<рабочая папка клиента>/
├── CLAUDE.md             правила работы, Claude читает их в каждом разговоре
├── aboutme.md            о бизнесе, на него ссылается CLAUDE.md
├── sostoyanie.md         состояние длинной задачи
├── resheniya.md          журнал решений владельца
├── platnye-servisy.md    если есть платные сервисы
├── zhurnal-pravok.md     если Claude правит сайты или рабочие системы
├── .claude/
│   └── settings.json     если есть файл с паролями
└── .env.secret           файл с паролями: заводит и заполняет клиент сам, Claude его не создаёт и не читает
```

Рабочая папка это папка, в которой клиент запускает Claude. Если непонятно, какая это, спроси клиента
и не начинай, пока не ответит.

## Как скачивать

Файлы нужны дословно, без пересказа.

- **Ты в Claude Code (есть терминал).** Скачивай командой `curl -fsSL <база>/<имя файла>`, а не
  инструментом чтения веб-страниц: тот пересказывает текст своими словами, и правила искажаются.
  Файл `settings.json` лежит на базе как `settings.json`, в папку клиента он ложится как `.claude/settings.json`.
- **Ты в веб-чате или в приложении без терминала.** Прочитай файлы по ссылкам, заполни их
  (порядок ниже) и выдай клиенту готовый текст. `CLAUDE.md` клиент вставляет в «Инструкции проекта»,
  остальные файлы загружает в «Файлы проекта». `settings.json` в веб-чате не нужен, пропусти его.

## Два вида текста в шаблонах

- **Управленческие правила**: весь текст вне тегов `<вопрос>`. Они одинаковые у всех клиентов, слово в слово.
  Не переписывай, не сокращай, не «улучшай» и не подстраивай их под клиента. Если клиент хочет изменить или
  убрать такое правило, не меняй его: запиши просьбу и довод клиента в «Открытые вопросы» файла `sostoyanie.md`,
  это решается с тем, кто дал клиенту эту ссылку.
- **Индивидуальное**: теги `<вопрос id="...">`. Их ты заполняешь по рассказу клиента и его ответам.
  Внутри тега бывает готовый текст («вместо тега вставь»): его вставляй тоже дословно, меняя только то, что
  стоит в угловых скобках.

## Порядок работы

1. **Проверь, что уже лежит в папке.** Если там есть свой `CLAUDE.md` или `aboutme.md`, ничего не
   перезаписывай. Покажи клиенту, чем его файл отличается от нашего, и спроси, что оставить.
   Правила клиента, которых у нас нет, сохраняются рядом с нашими.
2. **Скачай шаблоны** во временную папку, не сразу в рабочую.
3. **Начни с рассказа клиента.** Первый вопрос один и открытый: «Расскажите своими словами, чем занимается
   ваш бизнес и какая у вас цель на этот год. Голосом удобнее, можно длинно.» Не перебивай анкетой.
4. **Заполни `aboutme.md` из рассказа.** Всё, что клиент уже сказал, впиши сам. Потом задай по одному только те
   вопросы `А`, на которые в рассказе ответа нет. Цель и цифры (`А2`, `А3`) обязательны: без них не заполнить
   раздел целей в `CLAUDE.md`.
5. **Заполни теги `CLAUDE.md`** по порядку номеров `П`. Сначала посмотри, что уже известно из `aboutme.md`
   (сайты, валюта, системы с логином, почта сотрудников, трекер задач): такие вопросы не задавай, а предложи
   готовое: «Из вашего рассказа: сайтов два, на Тильде. Оставляю раздел про сайты, верно?»
   - Остальные вопросы задавай по одному, своими словами, коротко, с примером из подсказки в теге.
   - Если в теге есть готовый вариант, предложи его: «Предлагаю так: ... Подходит?»
   - Короткий или размытый ответ уточняй, пока не поймёшь. Цифры не додумывай.
   - Клиент не знает или хочет позже: оставь на месте тега строку `<!-- открыто: П7 -->` и
     занеси вопрос в «Открытые вопросы» файла `sostoyanie.md`.
6. **Замени каждый тег ответом**, записанным как правило или как факт, в стиле соседнего текста.
   Не «клиент сказал, что ...», а готовое правило: «Файл секретов: `.env.secret`».
7. **Сверь управленческие правила.** Весь текст вне тегов в итоговом `CLAUDE.md` должен совпадать с шаблоном
   слово в слово. Проверь сравнением файлов, а не на глаз.
8. **Покажи оба файла целиком** перед записью и дождись «да».
9. **Положи файлы в рабочую папку.** Остальные файлы из таблицы скачай и положи как есть,
   `platnye-servisy.md` и `zhurnal-pravok.md` только если они нужны по ответам (`П14`, `П16`).
   В `.claude/settings.json` замени `.env.secret` на имя файла секретов из ответа на `П10`: в трёх запретах
   и в хуке (там точки в имени экранированы: `\\.env\\.secret`). Если в папке уже есть `.claude/settings.json`,
   не заменяй его, а допиши запреты в `deny` и хук в `hooks.PreToolUse`. Файл секретов не создавай и не заполняй:
   это делает клиент сам.
10. **Проверь хук.** Попроси клиента перезапустить Claude в этой папке (хуки читаются при запуске), затем попробуй
   прочитать файл секретов командой `cat`. Должен прийти отказ «Файл секретов закрыт для Claude». Пришло содержимое
   или «нет такого файла» без отказа: хук не встал, разберись до того, как клиент положит туда ключи.
11. **Проверь правила.** Попроси клиента открыть новый разговор в той же папке и спросить:
   «Перескажи, чем я занимаюсь, какая у меня цель, что тебе нельзя без моего "да" и чем ты заканчиваешь длинную
   работу». Верный пересказ означает, что правила читаются. Ошибка: допиши это место и проверь ещё раз.

## Чего не делать

- Не переносить в файлы клиента ничего про того, кто дал эту ссылку: ни названий, ни адресов, ни примеров.
  Примеры в подсказках только поясняют вопрос.
- Не добавлять правил «на будущее» от себя. Правило появляется, когда что-то пошло не так, и
  тогда дописывается одной строкой с датой (как, написано в конце `CLAUDE.md`).
- Не менять управленческие правила, даже по просьбе клиента (выше, «Два вида текста»).
- Не ставить кроны, фоновые задания и автоматику: этот набор только про правила.
- Не просить у клиента пароли и ключи в чат. Ключи для программ клиент сам вносит в файл секретов, пароли людей
  хранит в менеджере паролей.
- Не ставить в текстах длинное тире, если клиент выбрал это правило (вопрос `П3`).
